# 01 Next Rule

This repository uses a modern App Router stack. Do not assume older Next.js, Tailwind, or shadcn conventions.

## Stack Snapshot

- Next.js 16 with the App Router
- React 19
- TypeScript
- Tailwind CSS v4
- shadcn/ui initialized for this repo
- `components.json` is the source of truth for shadcn setup
- Current shadcn base is `Base UI`, not `Radix`

## Routing And Rendering

- Use the App Router only. New pages and layouts belong under `app/`.
- Treat `page.tsx` and `layout.tsx` as Server Components by default.
- Add `"use client"` only when a file needs state, effects, event handlers, or browser APIs.
- Keep the client boundary as low in the tree as possible to avoid shipping unnecessary client JavaScript.

## Data And Mutations

- Prefer server-side data fetching in Server Components when the UI does not need browser-only logic.
- Use Server Actions for app-owned mutations such as forms and in-app state changes.
- Use Route Handlers in `app/api/**/route.ts` for public endpoints, webhooks, streaming, or integrations that are not just form mutations.
- Never expose secrets to Client Components. Environment variables and provider keys must stay server-side unless they are explicitly public.

## UI Conventions

- Prefer shadcn/ui primitives before building custom low-level UI from scratch.
- Add new shadcn components through the CLI when practical so the repo stays consistent with `components.json`.
- This repo currently uses the `Base UI` variant generated by shadcn. Do not mix in `Radix`-based snippets unless we intentionally migrate.
- Reuse `cn()` from `lib/utils.ts` for conditional class composition.
- Keep shared UI primitives in `ui/`. Feature-specific view code can live closer to the route or feature.

## Tailwind v4 And Styling

- Tailwind v4 is configured through `app/globals.css` and theme variables, not a `tailwind.config.ts` file.
- Prefer theme tokens such as `bg-background`, `text-foreground`, `border-border`, `text-muted-foreground`, and radius tokens instead of hard-coded colors.
- When changing the design system, update the CSS variables in `app/globals.css` first.
- Prefer utility classes and component composition over large custom global CSS blocks.
- Keep animations and one-off styling local unless they are clearly reused.

## Font Setup

- Keep the Geist font variables attached to the `<html>` element in `app/layout.tsx`.
- In Tailwind v4 `@theme inline`, use literal font-family values instead of circular CSS variable references for `--font-sans` and `--font-mono`.
- If typography unexpectedly falls back to serif fonts, check `app/layout.tsx` and `app/globals.css` before making wider styling changes.

## Quality Bar

- Keep ESLint passing before finishing work.
- Favor small, composable components over large multi-purpose files.
- Preserve TypeScript strictness. Avoid `any` unless there is a clear, justified boundary.
- Prefer framework defaults unless the repo already established a different pattern.

## Repo Hygiene

- Do not commit `.env.local`, local caches, or generated build output.
- Treat `components.json`, `package.json`, and `app/globals.css` as high-impact files. Review those changes carefully.
- If introducing a new dependency, prefer one that fits the existing Next.js plus shadcn ecosystem.

## When Unsure

- Follow the official Next.js App Router model first.
- Follow the current shadcn setup in this repo before copying examples from older articles.
- If a snippet assumes older Tailwind or older shadcn internals, adapt it to Tailwind v4 and this repo's `Base UI` setup before using it.
